# User journeys

One named person, one goal, start to finish, including the parts that are not on
a screen. A journey is written from outside the system and never mentions an
endpoint, a component or a table.

Each step carries what the person needs to see and what makes the step fail. The
failure column is the point: it is where requirements come from, and it is
usually the only place a real constraint on the API shows up before the API is
built.
