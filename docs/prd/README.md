# Product requirement documents

A PRD says what is being built and for whom, in the user's language, before
anybody has decided how.

It is mutable until the thing ships, and it is the only document here that is
allowed to contain an open question. If a decision inside it turns out to close
off alternatives, that decision leaves and becomes an [ADR](../adr/).

**The section that earns its keep is "explicitly not in this version."** A PRD
that lists only what is included documents a plan. A PRD that lists what was
asked for and deferred, with the reason, documents a decision, and stops the same
scope arriving again as a surprise halfway through.
